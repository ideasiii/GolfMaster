## 4.7 ⚠️⚠️ 推桿穩定度圖：哪些數字可以用（2026-09-10 定案）

### ⛔⛔ `processShortGameData` / `ShortGameData` ⛔ 完全不能重用

⚠️⚠️ 這一條最重要，⛔ 不要因為切桿頁有現成的落點圖就想接過來。

`ShortGameData.processAnalyz()` 的「落點」**⛔ 不是量到的落點**，
而是用**球飛行模型**幾何反推出來的（原始碼約第 360〜390 行）：

```java
yCoordYd = carryDistFt / 3.0;                              // 縱軸 ＝ 飛行距離
sideDeviationFt = carryDistFt * tan(LaunchDirection);      // 橫軸 ＝ 飛行距離 × 方向
sideSpinEffectFt = (SideSpin / 1000) * SIDE_SPIN_FT_PER_1000_RPM;   // 側旋修正常數
xCoordYd = (sideDeviationFt + sideSpinEffectFt) / 3.0;
```

對推桿來說這三行每一行都不成立：

| 問題 | 為什麼 |
|---|---|
| 用 `CarryDistFt` | ⛔ 推桿的球⛔ 不會飛，carry 這個值對推桿沒有意義 |
| 用 `tan(方向) × 飛行距離` | ⛔ 那是球在空中的偏移，⛔ 推桿是在草皮上滾 |
| 側旋修正常數 | ⛔ 那是**球飛行**的經驗係數，⛔ 對滾動的球無關 |

→ ⛔ **`landing_points`、`horizontal_deviation_yd`、`stdev_horizontal_yd`
　　⛔ 全部是球飛行模型的輸出，⛔ 一個都不能用在推桿頁。**
⭐ 這正好印證規劃 §3.1 原本就寫的：
「一致性落點圖是**新寫推桿版**，⛔ 不改 `ShortGameData.java`」。

⭐ **推桿版要做的事很單純**：直接畫 `shot_data` 的兩個原始量測值，
⛔ 不做任何幾何換算、⛔ 不套任何模型。

### 落點圖的兩軸（⛔ 兩軸都必須是量測值）

```
橫軸 = LaunchDirection 相對「自己的平均」   → 出球偏左 / 出球偏右
縱軸 = BallSpeed       相對「自己的平均」   → 推太強 / 推太弱
```

⛔ 軸標⛔ 不可以再寫「偏長／偏短」—— 縱軸現在是**力道**，⛔ 不是距離。
⭐ 這樣整張圖沒有一個值經過滾動模型，而且更名實相符：
它回答的是「你每一推的方向與力道有多一致」，⛔ 不是「球最後停在哪」。

### ⚠️⚠️ 一個一定要處理的方法論陷阱（Core 2026-09-10 給了具體答案）

**最近 N 推的 `DistToPinFt` 不會一樣。**
2 呎的推和 30 呎的推，`BallSpeed` 本來就差很多 ——
⛔ **那個離散度⛔ 不是「推得不穩」，是「推的距離不同」。**
⛔ 直接把最近 N 推的球速標準差當穩定度，會把一個正常球員判成不穩。

**⛔⛔ 不可以用「除以 DistToPinFt 正規化」這條路**

⚠️ 理由比「未驗證的假設」更硬：**那個模型是已知會偏的。**
等減速滾動下，速度與距離的關係是 **`v ∝ √d`**，⛔ **不是 `v ∝ d`**。
→ 線性正規化會**系統性地讓長推看起來太弱、短推看起來太強**。
⭐ 也就是說它⛔ 不是「可能不準」，是**可以預測它往哪個方向錯**。

⚠️⚠️ **但也⛔ 不要改用 `√d` 正規化** —— 那仍然是一個我們沒有量過的模型，
⛔ 只是換一個比較好聽的名字。⛔ 兩種都不做。

**⚠️ 「方向與推的長短無關」也是假設，⛔ 不是已知**

⭐ 但它**可以用手上的資料當場驗**：
把 `LaunchDirection` 依 `DistToPinFt` 分組，看離散度會不會隨距離變。

| 結果 | 怎麼辦 |
|---|---|
| 不變 | ⭐ 前提成立 → 寫進文件，從「假設」升格成「量過的事實」 |
| 會變 | ⚠️ 方向軸也有同樣的混淆，⛔ 只是先前沒人注意到 |

⚠️ Core 提到他們在這件事上留過痕：曾經把「窗長／拍攝條件污染」當成解釋寫進結論，
⛔ 那沒有量過，而且同型錯誤先前已經栽過一次。
⭐ **規矩：能驗的假設就去驗，⛔ 不要當前提用。**

**⭐ 定案的做法：分層 ＋ 只在有資料的地方畫**

| 軸 | 做法 |
|---|---|
| 方向軸（`LaunchDirection`）| 照原樣畫，⚠️ **但先跑上面那個驗證**，把前提寫成量過的 |
| 力道軸（`BallSpeed`）| **依 `DistToPinFt` 分層**，基準是「⭐ 自己在**同一個距離帶**的平均」，⛔ 不是全域平均 |

⚠️⚠️ **某個距離帶樣本不足時，那一軸標「資料不足、⛔ 不畫」。**
⛔ **絕對不可以退回全域平均** —— 退回去就等於偷偷做了線性正規化的事，
⛔ 而且畫面上看不出來、沒有人會發現。

⭐ 這跟評估側的既有原則是同一條：**分來源列、⛔ 不合併**；
任何會縮小樣本的操作，把縮小的幅度一起報出來。
→ 這張圖的等價做法是**把「這一帶只有 N 推」寫在圖上**。
